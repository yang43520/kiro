# 创意动画生成（animation-brief）

全程用中文和用户沟通。工作分两步：

1. **创意建议**：用户说出想法后，先给出几个创意方向，等用户选定。
2. **输出文件**：用户选定方向后，输出主文件、剧本文件和考点说明文件。写文件时，必须按类目把**制作方法底线、专业术语、内置/开源插件**写进 Prompt。

**档位下限**：创意方向和最终任务默认都是**进阶档或上限档**。只有用户明确提到"基准档"时，才可以出基准档（见第 2 节）。

## 0. 先读规则文件

| 文件 | 用途 |
|---|---|
| `.kiro/steering/animation-taxonomy.md`（没有时读 `references/animation-taxonomy.md`） | 类目表和标签，只能用表里已有的类目路径 |
| `references/test-point-guide.md` | 出题指南：19 个考点的考察核心和示例、强耦合规则、档位配方 |
| `.kiro/steering/animation-test-points.md`（没有时读 `references/test-points.md`） | 考点名称、分级和档位配方的执行口径 |
| `references/production-baseline.md` | **制作方法底线、专业术语、推荐插件**：第一部分按类目表的 33 个二级类目列出，第二部分是 10 个技术模块（T1–T10） |
| `references/realism-checklist.md` | 写实细节清单 |
| `references/single-file-template.md` | 主文件和剧本文件的模板 |
| `.kiro/steering/animation-output-spec.md` | 输出规格，默认 1280×720、30 帧/秒 |

## 1. 第一步：创意建议

用户说出想法后，**先给创意方向，不直接写文件**。只有用户明确说"直接写""就按这个写"，或给的是完整的提示词时，才跳过这一步。

- 给 3–5 个方向，每个方向都贴合用户的想法，但在主体、场景、动作或镜头上有明显区别；避开已经做过的题材（看仓库里已有的任务文件夹）。
- 用表格列出，列固定为：

  `方向｜类目路径｜画面（约 12 秒）｜亮点｜档位与考点｜制作方法与插件｜制作难度`

  - **类目路径**：按类目表选到三级。
  - **档位与考点**：按出题指南的配方选一组强耦合的考点，写出编号、名称、分级和档位。用户没有提到基准档时，每个方向都必须是进阶档或上限档。
  - **制作方法与插件**：写出对应的技术模块编号，以及 1–3 个最关键的内置或开源插件。
- 表格后推荐 1–2 个方向，并用一两句说明理由。
- 只在会明显改变结果的问题上提问，每个问题都给默认答案，让用户可以只回"按默认"。
- 用户同时提出几个任务时，先说清楚先做哪个，其余的排队。

## 2. 定题目档位和考点

- 先定档位，再按 `references/test-points.md` 的配方选出 1 组强耦合的考点，然后让剧本里的关键动作正好落在这些考点上。
- **默认至少进阶档**：用户没指定档位时定为进阶档；题材本身适合更难的组合，或用户要"更难""更惊艳"时定为上限档。最低合格组合是单个 L3，或强耦合的 L2 + L2（各自最多附带 2 个 L1）。单个 L2、L2 + L1、2～3 个 L1 都只是基准档，不能作为默认方案。
- **基准档只在用户明确提到时使用**：用户明确说了"基准档"时，才按基准档配方出题，并在考点说明文件里写"**档位来源**：用户指定"。
- **题材只撑得起基准档时**，不要换掉用户的题材，按下面的方法在同一主体或同一条因果链上升到进阶档：

  | 原来的基准档组合 | 升到进阶档的方法 | 示例 |
  |---|---|---|
  | 单个 L2 | 在同一主体上加一个互相制约的 L2 | 3 复杂轨迹 + 4 车轮防打滑（同一辆车跑盘山路） |
  | 单个 L2 | 把核心换成同一机制上的 L3 | 9 拆解组装 → 由机械臂抓取零件完成组装，核心变为 5 |
  | 2～3 个 L1 | 把其中一个基础维度深化成 L3 | 2 急停 → 急停时附属物甩出，核心变为 6 |
  | L2 + L1 | 加一个在同一接触链上的 L2 | 14 方柱矩阵波浪 + 10 波浪顶起上方木块 |

- 强耦合规则不变：为了凑档位而摆一个互不相干的主体，仍然无效。
- 所有考点必须作用在同一个核心运动主体上，或在同一条接触、抓取、因果链上；不能为凑考点在画面里摆互不相干的主体。

## 3. 制作方法底线、专业术语和插件（写进 Prompt）

写文件前，按下面的顺序从 `references/production-baseline.md` 里取内容：

1. 在第一部分找到本片的**二级类目**那一行，记下它的制作方法底线、专业术语、推荐插件和对应的技术模块。
2. 到第二部分读这些**技术模块**，补全细节底线和术语。
3. 加上**通用底线**：禁止用基本几何体拼凑、细节密度、尺度参照、PBR 贴图或程序化材质、物理天空或场景灯光、接触阴影、AgX 色彩管理、足够的采样。

然后这样写进 Prompt：

- **重点效果要求**：每一条都写清"要看到什么画面"，并用专业术语写出"用什么方法做"。例如"山体用高精度地形网格，经过侵蚀模拟和置换，有节理、断崖和碎石坡"。
- **另外一段**：先写通用底线和本类目的底线（禁止项），再写素材规则，最后用一句"可借助 ……（内置）、……（开源）等插件"给出插件建议，只作建议，不写成必须安装的前提。
- **剧本正文**：场景、材质和灯光段落里也要体现同样的方法和术语，和重点效果要求保持一致。

**插件规则**：只用 Blender 内置功能、官方扩展平台的免费扩展和开源免费插件；**收费的商业插件一律不考虑**，也不写进 Prompt。插件只用它的建模、生成、模拟、绑定功能，不用它附带的成品模型和预设资产。

**素材规则**：可以用图像贴图（PBR 贴图）；贴图以外的外部素材都不能用：现成模型、环境贴图 HDRI、扫描模型、体积数据、素材库里的成品资产。Prompt 里要写"所有模型在 Blender 里建模，环境光用物理天空或场景灯光"。

**风格化任务**（图形动画、卡通角色、三渲二等）：底线换成"设计质量"，即倒角一致、造型统一、配色和节奏讲究，不套用照片写实的要求。

## 4. 硬性规则（每个任务都适用）

| 项目 | 规则 |
|---|---|
| 档位 | 默认至少进阶档；只有用户明确提到基准档时才用基准档 |
| 时长 | 8–12 秒，默认约 12 秒；内容实在放不下时最长约 15.6 秒，但必须先征得用户同意 |
| 运动 | 主体自身必须有真实可见的运动或形变，不能只靠镜头运动 |
| 声音 | 无声音 |
| 规格 | 16:9，1280×720，30 帧/秒（以 output-spec 为准），全文写成同一组数值，并写出总帧数 |
| 软件 | 主文件第一句是"基于《X剧本》，用 Blender 5.0.0 制作……" |
| 内容 | 默认不出现人物、可读文字和真实品牌；造型原创，不照搬现有电影、游戏或真实产品（用户明确要求还原时除外，并提示版权） |
| 插件 | 只用内置和开源插件，不用商业插件 |
| 素材 | 只允许贴图；其他外部素材都不能用 |
| 提示词用语 | 描述画面、运动、节奏和镜头，可以用专业动画术语；严禁出现"写脚本/写代码"、代码指令、API 函数名、属性变量名或编程步骤 |
| 镜头 | 默认一镜到底；用了剪辑就要在剧本里写清每个镜头 |

## 5. 第二步：输出文件

- 每个任务输出三个文件，放在同一个任务文件夹里，都用 UTF-8 带 BOM（Python 用 `encoding='utf-8-sig'` 读写）：
  - `<标题>.md`：Prompt 与剧本合在一起的主文件；
  - `<标题>剧本.md`：只有剧本，内容是 `# <标题>剧本` 加上主文件里"以下是《<标题>剧本》："之后的剧本正文，逐字一致；
  - `<标题>考点说明.md`：**内部校验用，不交给制作方**。写题目档位、档位来源、耦合链、考点表和最高分级，格式见 `references/single-file-template.md` 末尾，内容和回复里的考点说明一致。
- 交给制作方的只有主文件和剧本文件。
- 主文件结构严格按 `references/single-file-template.md`，只有「Prompt 与剧本」一节：
  1. 开头一段"基于《X剧本》，用 Blender 5.0.0 制作……"，写明时长、风格、规格；
  2. "重点效果要求如下："按编号逐条写，每条用通俗标题，写清画面和制作方法；
  3. 一段"另外，……"写底线、禁止项、素材规则、插件建议和可调整范围；
  4. "以下是《X剧本》："接剧本正文：基本设定 → 场景布局 → 材质细节 → "第 X–Y 秒（段落名）"逐段动作和镜头 → 灯光与成像要求。
- 主文件和剧本文件里不能出现"考题""考点""考察"字样，也不写考点编号、L1–L4 分级、题目档位、耦合链和类目；考点和档位只写在考点说明文件和回复里，类目只在回复里说明。
- 修改时三个文件一起改：剧本文件始终从主文件同步；剧本里的关键动作变了，考点说明里的"作用对象与时段"和"在片中的体现"也要跟着改。
- 文件名和标题都不带版本号。

## 6. 写作要求

- 所有尺寸、距离、速度、时间都写成具体数字，并说明是参考值。
- 动作按秒写清"谁在什么时候做什么"；第一帧就要在动，结尾停在主体仍在运动的时刻。
- 写实类任务再按 `references/realism-checklist.md` 补材质和结构细节；用户说"更写实"时，按清单和制作底线加细节。
- 检查物理和镜头逻辑，例如镜头要停到某物的后上方，那么它必须先从镜头下方经过。
- 重点效果要求和剧本正文对应的段落说同一件事，数字一致。

## 7. 校验（每次修改后都要跑）

```bash
python3 <skill 目录>/scripts/check_brief.py <任务文件夹>/<标题>.md
```

主文件检查项：
- 剧本文件是否存在、是否和主文件里的剧本正文逐字一致；
- BOM、开头句式、时长，分辨率、帧率和总帧数是否一致；
- 有没有"重点效果要求如下"和"第 X–Y 秒"分段；
- 代码类用语；
- 文件里有没有误写考点、分级、档位或类目；
- 有没有贴图以外的素材、商业插件，以及是否缺少插件建议。

考点说明文件检查项（脚本会随主文件一起检查 `<标题>考点说明.md`）：
- 文件是否存在、BOM、标题是否和主文件一致；
- 考点编号、名称、分级是否和考点表完全一致；
- 考点组合是否符合所写档位的配方；
- **档位下限**：基准档且"档位来源"不是"用户指定"时报 ERROR；
- 是否写了档位来源、耦合链和最高分级，最高分级是否正确。

强耦合（考点是否作用在同一主体或同一条因果链上）脚本查不出来，回复前要自己核对。旧格式（`<标题>_制作需求.md`）按原来的规则检查。有 ERROR 必须修好；WARN 要逐条确认。

## 8. 旧格式（仅用于修改旧任务）

2026-11-19 以前的任务是"剧本 + 制作需求"两个文件，模板见 `references/script-template.md` 和 `references/brief-template.md`。修改这些旧任务时保持原格式，除非用户要求转换成新格式。

## 9. 提交

- 遵守仓库的分支规则：当前分支不是 main/master 时直接提交到当前分支；是默认分支时新建分支。
- `git add` 只加明确的文件路径；提交后 `git push`，再用 `gh api "repos/<owner>/<repo>/git/trees/<branch>?recursive=1" --jq '.tree[].path'` 确认文件已经在远端。
- 回复里给出 GitHub 链接：`https://github.com/<owner>/<repo>/blob/<branch>/<路径>`。

## 10. 效果图（只在用户要求时做）

- 默认按剧本里的 3 个关键时刻各出 1 张，1280×720，放在 `<任务文件夹>/效果图/`。
- 做法见 `references/mockup-guide.md`；下载 Poly Haven 资源用 `scripts/fetch_polyhaven.py`。效果图只用于内部预览，用到的模型和 HDRI 不能写进 Prompt。
- 先出低分辨率测试图，确认没有明显问题后再渲染终稿；交付时如实说明效果图和剧本的差距。

## 11. 回复用户的格式

**第一步（创意建议）的回复**：创意方向表格 → 推荐的方向和理由 → 需要用户决定的问题（带默认答案）。

**第二步（输出文件）的回复**，依次包含：

1. 三个文件的链接（主文件、剧本文件和考点说明文件），并注明考点说明文件不交给制作方。
2. 一张时间线表（时间｜段落｜画面）。
3. 类目（完整路径）和一句归类理由。
4. **考点与指南说明**：表格列出每个考点的编号、名称、分级、出题指南里的考察核心（一句话），以及在本片中的体现。
5. **考察点与难度情况**：
   - 题目档位（默认至少进阶档；基准档要说明是用户指定的），以及它对应档位配方里的哪一条组合；
   - 耦合链；
   - 难度来源和最容易穿帮的点；
   - 片中有但没有列为考点的效果，以及升档的调整方法（降档只在用户提到基准档时才给）。
6. **制作方法说明**：本片对应的技术模块、写进 Prompt 的关键底线和术语，以及推荐的内置或开源插件。
7. "我自己定的默认设定"（编号列出），以及仍在等用户回答的问题。

不写开场白和结尾客套话，不复述用户已经知道的内容。
