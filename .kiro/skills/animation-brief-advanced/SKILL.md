# 进阶版动画创意（animation-brief-advanced）

全程用中文和用户沟通。目标是**一次就交出能通过验收的方案**：事件有起因、过程和结果，画面元素丰富，动态形式多，还原真实，光线、氛围、构图和色彩达到电影级，细节精致，同时主次清楚、没有穿模和因果断裂。**所有这些都写进主文件（提示词）本身，不另出剧本文件。**

主文件最终交给模型，由模型在 Blender 里把动画做出来。进阶版要求把镜头、构图、光线、颜色和渲染都交代清楚，但**写法要像懂行的导演当面交代**：口语化、数字取整、能笼统的地方笼统、适当缩写，不写坐标、色值、零点几秒这类像机器算出来的内容。**口语化不等于省掉专业术语**，术语一律照原样写。写法见 `references/advanced-execution.md`。

本 skill 是 animation-brief 3.4 的进阶版，和它并存；3.4 的任务和旧格式任务仍用 animation-brief 处理。

工作分两步：

1. **创意建议**：用户说出想法后，先给出几个创意方向，等用户选定。
2. **输出文件**：用户选定后，输出主文件、考点说明和 `rubric.json` 三个文件。

**档位下限**：创意方向和最终任务默认都是**进阶档或上限档**。只有用户明确提到"基准档"时，才可以出基准档（见第 2 节）。

## 1. 第一步：创意建议

用户说出想法后，**先给创意方向，不直接写文件**。只有用户明确说"直接写""就按这个写"，或给的是完整的提示词时，才跳过这一步。

- 给 3–5 个方向，每个方向都贴合用户的想法，但在主体、场景、动作或镜头上有明显区别；避开已经做过的题材（看仓库里已有的任务文件夹）。
- 用表格列出，列固定为：

  `方向｜类目路径｜起因 → 过程 → 结果｜画面元素｜动态形式｜档位与考点｜制作方法与插件｜制作难度`

  - **类目路径**：按类目表选到三级。
  - **起因 → 过程 → 结果**：各用一句话；结果必须是能在画面里看见的终态，例如"化形完成的大鹏在晨光里展翼滑翔"。
  - **画面元素**：按"前景：…；中景：…；远景：…"写，每层 2–3 个，标出尺度参照。
  - **动态形式**：按 `references/richness-dynamics.md` 的代号列出不少于 6 种，主动作放在最前。
  - **档位与考点**：按配方选一组强耦合的考点，写编号、名称、分级和档位。
  - **制作方法与插件**：技术模块编号，加 1–3 个最关键的内置或开源插件。
- 每个方向都先对照 3.7 的数量硬指标，再按所属一级类目的专项标准自查，例如场景类不能只有一个主体加通用背景，产品类要有旋转之外的展示过程，图形类不能只靠一种动作重复。
- 表格后推荐 1–2 个方向，并用一两句说明理由。
- 只在会明显改变结果的问题上提问，每个问题都给默认答案，让用户可以只回"按默认"。
- 用户同时提出几个任务时，先说清楚先做哪个，其余的排队。

## 2. 定题目档位和考点

- 先定档位，再按 `references/test-points.md` 的配方选出 1 组强耦合的考点，然后让关键动作正好落在这些考点上。
- **默认至少进阶档**：用户没指定档位时定为进阶档；题材本身适合更难的组合，或用户要"更难""更惊艳"时定为上限档。最低合格组合是单个 L3，或强耦合的 L2 + L2（各自最多附带 2 个 L1）。单个 L2、L2 + L1、2～3 个 L1 都只是基准档，不能作为默认方案。
- **基准档只在用户明确提到时使用**：用户明确说了"基准档"时，才按基准档配方出题，并在考点说明文件里写"**档位来源**：用户指定"。
- **题材只撑得起基准档时**，不要换掉用户的题材，在同一主体或同一条因果链上升档：

  | 原来的基准档组合 | 升到进阶档的方法 | 示例 |
  |---|---|---|
  | 单个 L2 | 在同一主体上加一个互相制约的 L2 | 3 复杂轨迹 + 4 车轮防打滑（同一辆车跑盘山路） |
  | 单个 L2 | 把核心换成同一机制上的 L3 | 9 拆解组装 → 由机械臂抓取零件完成组装，核心变为 5 |
  | 2～3 个 L1 | 把其中一个基础维度深化成 L3 | 2 急停 → 急停时附属物甩出，核心变为 6 |
  | L2 + L1 | 加一个在同一接触链上的 L2 | 14 方柱矩阵波浪 + 10 波浪顶起上方木块 |

- 所有考点必须作用在同一个核心运动主体上，或在同一条接触、抓取、因果链上；为凑考点或凑丰富度摆一个互不相干的主体，仍然无效。

## 3. 一次合格的设计规则（写文件前逐条落实）

### 3.1 事件完整

- 起因在第 0–2 秒内出现，过程按秒推进，**结果在结尾前至少完整展示 1–1.5 秒**，观众能看清终态。结尾段保留次级运动（余摆、飘动、滴落），画面不能完全静止，但主动作已经完成，不能"没做完就结束"。
- 每个关键动作写清谁先谁后、谁引起谁；这些先后关系写进"底线和限制"里不能改变的顺序。

### 3.2 主体自己要动

主动作必须是主体自身的位移、旋转、形变或部件相对运动。镜头运动、剪辑和亮灭都不能代替主体运动。

### 3.3 画面丰富、动态够多

按 `references/richness-dynamics.md` 写满最低要求：

- 前景、中景、远景各至少 2 类元素，主题元素不少于 8 类，至少 1 个尺度参照，故事细节 5–10 个，材质不少于 4 种；
- 动态形式不少于 6 种，主体主动作层、次级层、环境响应层（至少 2 个由主体引起）、氛围层各至少 1 种；
- 每种动态都写出来源和时间；每 2–3 秒至少一个新变化；因果链至少 3 环。
- **重模拟最多 2 种**：液体模拟、烟雾或烟火模拟、布料模拟、大规模刚体模拟这几类，一条片子里最多用 2 种。其余动态用骨骼、驱动器、形态键、粒子、程序化动画这类轻量做法凑够数量。宁可少一个效果，也要让每个效果做得精。

### 3.4 主次清楚，别堆叠

- 关键时刻主体一般不小于画面宽度的三成，关键过程不出画、不被遮挡，也不被景深或运动模糊掩盖；
- 氛围层的亮度和密度低于主体；烟、雾、粒子、水花不能遮住关键接触、形变和结果；
- 灯光克制：曝光以主体为准，辉光只在最亮处，别加镜头光晕、星芒、横向光条和光雾。

### 3.5 提前堵住重点扣分项

穿模、悬空、滑步、漂移、动作突跳、无故换形、部件消失、材质突变、亮度跳变、闪烁、卡顿、因果断裂：

- 每个关键接触写"对准、贴住、别穿过"；
- 每个变速、转向、形变都写出原因，动作曲线带缓入缓出；
- 设计性的外观变化写清起止时间和依据；
- 用数字核对物理和镜头：速度 × 时间 = 距离，主体在画面里的占比按焦段算（24 毫米镜头水平视角约 74°，画面宽度约等于 2 × 距离 × 0.75）。

### 3.6 按一级类目落实专项标准

| 一级类目 | 必须写进方案的内容 |
|---|---|
| 角色动画 | 角色的意图和反应；起动前的预备动作；身体各部位协调参与；附属部位的二级跟随；每个支撑和接触 |
| 产品动画 | 至少一种旋转之外的展示过程（开合、拆解、组装、功能运行、内部显露）；整体—局部—过程的递进；不少于 4 种可辨材质；清楚的产品终态 |
| 场景动画 | 主体加周边环境加配套内容；三层空间和疏密主次；主要对象的内部结构；与主题相符的自然动态 |
| 载具动画 | 完整的运行过程（行进、转向、起降）；路径、朝向和姿态匹配；车轮、旋翼等部件与运行状态联动；尾迹、水花、扬尘的来源和方向 |
| 图形动画 | 不少于 3 组元素、3 级层级；错时、递进、聚散、形变等多种编排；元素之间的触发关系；目标形态清楚出现 |
| 现象动画 | 触发、发展和结果；连续可追踪；与容器、支撑、地面的边界；目标材质的动态特征；后续状态（落稳、消散、回弹） |
| 科教演示 | 明确的知识目标；结构和规律准确；剖切、分层、对比、轨迹等演示方法；辅助标识默认用箭头、颜色和引导线 |

### 3.7 数量硬指标（验收逐项数，rubric 各列一个关键项）

| 适用范围 | 硬指标（rubric 的维度名） | 要求 |
|---|---|---|
| 所有类目 | 结构分件 | 核心主体的独立结构分件 ≥ 4 个，在“场景和主体”里逐个写出，并在动作里写出各自的运动 |
| 所有类目 | 递进阶段 | 可识别的递进动作阶段 ≥ 3 个，前一阶段的结果是后一阶段的起因 |
| 所有类目 | 布光层次 | 有效布光 ≥ 2 层，在“灯光和画面”里写清每层的光源、方向和作用 |
| 产品动画 | 产品行为 | ≥ 2 种非运镜类产品行为（例如拆解 → 内部运作 → 复位闭合，加指示灯或屏幕反馈） |
| 产品动画 | 卖点细节 | ≥ 2 处卖点细节，每处连续可辨 ≥ 1 秒，写出各自的时段 |
| 产品动画 | 组件数量 | 独立建模组件 ≥ 8 个，逐个写出 |
| 产品动画 | 材质种类 | ≥ 3 种物理属性截然不同的材质 |
| 场景动画 | 资产种类 | 独立造型资产 ≥ 8 种，逐种写出 |
| 场景动画 | 环境动态源 | ≥ 3 类相互呼应的自然或环境动态源，写出谁带动谁 |
| 场景动画 | 三层空间 | 前景（遮挡或引导）+ 中景（核心主体）+ 远景（天际线或背景环境） |
| 载具动画 | 状态转换 | 普通运行至少 2 次明确的状态转换（例如启动 → 行驶 → 转向）；持续巡航改写稳定运行和环境响应 |
| 图形动画 | 组织状态 | ≥ 3 个有区别的组织状态、2 次不同类型的转换，只改速度不算 |
| 图形动画 | 元素关系 | 至少一组可追踪的触发、跟随、传播或组合关系 |
| 现象动画 | 触发与交互 | 完整的触发 → 发展 → 结果，至少一次和边界、对象或群体的交互并产生可追踪的变化 |
| 科教演示 | 观察方法 | 至少一种真正帮助理解的观察方法，关键关系连续可观察 ≥ 2 秒 |

主文件里要把这些数量**明确写出来**（列出分件、阶段名、光的层次、资产种类等），rubric 才能依据主文件来验收。

### 3.8 主文件的画面要求（进阶版 1.7，全部写进主文件）

写法见 `references/advanced-execution.md`，建模见 `references/anti-primitive.md`，表面细节见 `references/surface-detail.md`，防穿模见 `references/anti-clipping.md`，动植物见 `references/organisms.md`，动物展开写见 `references/animals.md`，基调见 `references/visual-tones.md`，动态分类见 `references/richness-dynamics.md`。下面按主题列出要写到什么程度：

| 主题 | 写在哪 | 要写到什么程度 |
|---|---|---|
| 风格 | 开头 | 只写一个片种参照（"像自然纪录片里的航拍""像高端腕表广告的黑棚"），不点名具体作品；从基调表的禁忌里挑 2–3 条写进"底线和限制" |
| 视觉基调 | "灯光和画面"第一句 | "视觉基调：<基调名>。"按题材和使用场景选，光比、焦距和 AgX 观感在这一行的范围里；大场景穿行用能上广角的基调（自然纪录、奇幻史诗、夜景都市），别为了"暖"选温馨童话 |
| 镜头和构图 | 每个时段段落 | 镜头在哪、大概多远、多少毫米、怎么动、为什么动；用了哪种构图；至少 2 段写主体在画面里占多大；对角线和三分法同一条片子里各最多用一段；写视线和留白往哪边；全片有特写、焦点转移和光圈 |
| 动态 | "动作和镜头" | 最后一句总述一直在动的东西（说法自己定），至少 8 样，要有远处的；动态形式按 A–N 分类至少 10 类，主动作、次级、环境响应、氛围四层都有；每 2–3 秒有新变化；重模拟最多 2 种，其余用轻量做法 |
| 还原 | "关键效果和做法" | 每条带一个取整的真实数值（数字加单位）；至少 2 条写做不出来时的退路 |
| 打光 | "灯光和画面" | 至少 3 层光，每层写方位、软硬（光源多大、影子边软还是硬）、动机（这束光在场景里从哪来）和作用；主光写色温，写一个光比；至少有轮廓光、逆光或实用光中的一种；写主光在片中怎么变；一层克制的大气效果 |
| 色彩和色调 | "灯光和画面" | 主色、辅色、点缀色用颜色词写，并写大概的面积比例（一般六成、三成、一成）；写饱和度上限和冷暖关系；一句色彩脚本；一句最亮的是什么；主体和背景差几档；哪里允许接近纯黑、哪里不能爆白 |
| 粒子 | "关键效果和做法" | 每种粒子写大小（带单位）、密度、生命周期、前后分层（前景的少而大、虚焦，远处的密而小）和怎么被光照到（多数只在逆光里看得见） |
| 质感 | "关键效果和做法"里专写材质的那一条 | 至少 3 种主材质各写一个可测的物理特征（带数字和单位）和高光的宽窄锐糊，靠这些把材料分开；每条片子有自己的质感重点，别都写成"湿的" |
| 建模 | "场景和主体" | 每个主体写从什么起形、轮廓哪里粗哪里细、部件怎么长在一起、三级起伏和个体差异；正文里不能正面写"用球体做……""拿圆柱当……"（图形动画/几何图形类除外）；大场景里的崖壁、远处石墙、窗洞、屋顶、雪山、瀑布和水面按 `references/anti-primitive.md` 第五节写到形状和尺寸，置换要推出真实几何 |
| 材质细节 | "场景和主体"和专写材质的那一条 | 植物、动物、建筑按 `references/surface-detail.md` 写：每种主要材料一个带单位的起伏或尺寸、至少两层风化或附着（写清在哪、为什么）、接触带、个体差异，有一段主光擦过这些表面；出现树时写根张、截面收分、枝领或伤痕里的两样，树皮写树种特征、沟深和贴图方向；出现建筑时按高度和朝向写至少两处风化；风格化任务按该文件第六节写，不叠写实风化 |
| 动物（1.7） | "场景和主体"和"关键效果和做法" | 写实场景里动物占了一块、有近景或在做动作时，按 `references/animals.md` 写：体长和部位比例、附肢和羽鳍的数量、表皮尺寸和沾了什么环境、动作的真实数值（步态顺序、扇翅或摆尾频率、速度）、用哪套 Rigify 模板和怎么接触（锁脚、抓握、吃水线），群体有个体差异；rubric 加关键项"动物形体与动作" |
| 动植物 | "场景和主体"和"关键效果和做法" | 动植物做主体或占画面一大块时，写结构拆解（按相对体长写比例，写清附肢、节数、花瓣数、分枝级数）、表皮、动作规律和真实数值、用哪种内置功能做；每秒十几次以上的振翅写成运动模糊的虚影或按高速摄影放慢 |
| 细节 | "场景和主体" | 大形、中形、小形三个术语；一句话列出近看要看得到的小细节，至少 8 样，每样写到"什么东西上的什么痕迹" |
| 防穿模 | "关键效果和做法"和"底线和限制" | 每条有接触的效果写清谁和谁接触、用什么方法防（反向动力学加地板或缩裹约束、锁脚、碰撞体厚度、碰撞距离、步数、最小间距、避让碰撞等）、安全距离多大；用了重模拟的那条必须写碰撞体或障碍物的做法；"底线和限制"里一句接触清单，列 3–5 个"第 S 秒 + 谁和谁"，写明用线框和 X 射线视图逐帧看；原有的"别让 A 穿过 B"保留 |
| 自查 | "场景和主体" | 一句灰模自查，例如"开工前先渲两张灰模，一张侧面剪影、一张四分之三角度，对比例，看有没有几何体拼出来的地方"（说法自己定）；动植物的比例也用这一句来查 |
| 海报帧和渲染 | "灯光和画面" | 海报帧 2–3 个时刻，写明先渲小图自查；一句渲染（引擎、采样、透射反弹、有体积时的体积步长、AgX 观感、暗角和颗粒）；画面里有大量镜面或玻璃物体时，按 `references/advanced-execution.md` 第 11 节写防噪点的做法 |
| 优先级 | "底线和限制" | 一句话说做不完时先顾哪几条，再写哪些先后顺序不能乱 |

**不要写**：坐标、看向点、主体在画面的精确小数位置、传感器参数、精确的对焦距离、十六进制色值、每层光的瓦数、零点几秒的间隔、三位以上的小数、推导出来的物理量、带时段的动态清单、计数开头的清单、每段相同的句式。主文件一般控制在 6,500 字以内，超过 7,000 字检查脚本会提醒。

**每条片子用自己的话**：渲染、曝光、焦点、海报帧、结尾、替代做法这些每条都有的句子，换成这条片子自己的说法；文档里的例句只是示意，不要照抄，也不要从别的任务里整句搬。句子换掉，里面的专业术语要留下。同一批创意里鸟群、晾衣这类元素别反复出现。

**风格不叠加**：每条片子只有一个主风格；最多借一种别的手法，而且只借镜头或光的做法（例如"微距的镜头做法借自美食片"），不借渲染风格（不写"带一点水墨感"）。视觉基调、风格参照、色彩基调和灯光氛围标签要是一套。下面这些组合不要叠在一起：

| 方面 | 不要叠在一起 | 为什么 |
|---|---|---|
| 渲染 | 照片级写实 + 水墨、山水画、三渲二、平涂描边 | 两套着色体系，只能二选一 |
| 渲染 | PBR 写实材质 + 低多边形、体素造型 | 写实光照会暴露方块和折面，像拿错了贴图 |
| 造型 | 卡通比例 + 照片级写实的皮肤或毛发 | 恐怖谷 |
| 景深 | 微距或移轴的浅景深 + 宏大场景、巨物 | 浅景深会把巨物拍成模型 |
| 运镜 | 纪录片式的稳 + 史诗式的大幅升降环绕；手持感 + 产品广告 | 两种运镜语言，取中间值哪种都不像 |
| 节奏 | 定格跳帧 + 运动模糊、平滑的物理模拟；夸张挤压拉伸 + 写实物理模拟 | 一个一顿一顿，一个要求连续；一个讲弹性，一个讲重量 |
| 光 | 黑棚低调 + 体积雾；高调纯白 + 霓虹彩光 | 雾把黑位抬成灰；白底上的彩光只会发脏 |
| 色彩 | 霓虹高饱和 + 东方意境的低饱和；两个互补色对撞 + 第三种强主色 | 饱和度策略相反；三个强色互相抵消、发泥 |
| 色彩 | 本身就很鲜的题材（霓虹、原色玩具、糖果）+ AgX Punchy | Punchy 自带饱和提升，会溢色、丢亮暗部细节 |
| 后期 | 胶片颗粒、暗角、辉光、光晕、浓雾全都叠满 | 每样只该一点，叠满了就脏 |
| 题材 | 东方神话 + 北欧或西式视觉符号；赛博 + 水墨；中式古建 + 哥特 | 文化符号打架，没有统一气质 |
| 参照 | 两个片种参照，或"像 A，又有 B""只是……一点""带一点……感" | 等于给两套标准 |

**例外**：写实地拍玩具（积木小人、胶囊人、木偶、微缩模型）可以接受，主体是风格化的玩具，拍法和材质按真实的玩具来，镜头和光按真实摄影来。

**例外：双世界接缝**（用户明确要求两个世界同框时才用）：两个题材的世界可以出现在同一条片子里，但必须满足这几条：两边都按照片级写实来做，用同一套渲染、同一套镜头语言；两边之间有一道看得见的接缝作为分界，接缝以外的地方两套符号不混在一起；视觉基调按镜头最后停留的那个世界选，另一个世界的光比、色温也要落在这个基调的范围里（例如黄昏的森林配雨夜都市）；两边交换的东西（风、落叶、雨、光）都要有物理上说得通的来去；接缝的边是干净的几何边界，不加辉光、光晕和光雾。

考点说明里写"**规范版本**：进阶版 1.7"和"**视觉基调**：<基调名>"。rubric 要有"动态密度""电影级画面""细节精致度""海报帧与视觉基调""接触与防穿模"五个关键项。

## 4. 制作方法底线、专业术语和插件

写文件前，按下面的顺序从 `references/production-baseline.md` 里取内容：

1. 在第一部分找到本片的**二级类目**那一行，记下它的制作方法底线、专业术语、推荐插件和对应的技术模块。
2. 到第二部分读这些**技术模块**，补全细节底线和术语。
3. 加上**通用底线**：禁止用基本几何体拼凑、细节密度、尺度参照、PBR 贴图或程序化材质、物理天空或场景灯光、接触阴影、AgX 色彩管理、足够的采样。

**先列清单再动笔**：把上面 1–3 步取到的内容，写成考点说明里的"## 制作底线清单"（格式见模板），列出二级类目、技术模块、本片要用的专业术语、推荐插件和通用底线。主文件写完后，逐条核对清单里的每一项都写进去了。

然后这样写进主文件（3.3 起恢复为硬规则）：

- **关键效果和做法**：每一条都写成"要看到什么画面 + 用什么方法做（带专业术语）+ 别怎样"三段。例如"山体用高精度地形网格，经过侵蚀模拟和置换修改器，三平面投影贴图防止拉伸；别让山体像光滑的锥体"。**至少 1 条**专门写材质和建模做法，标题里带"材质"或"质感"，写清主要材质的做法：例如"硬表面建模，硬边用倒角修改器加加权法线，喷涂面的边缘磨损用曲率遮罩，凹处积灰用环境光遮蔽"。
- **场景和主体**：建模和材质段落里也要用同样的术语写做法，不能只写"看起来像什么"；主体按"大形 → 部件 → 小细节"三层写，写出近景贴图精度（如 4K）和一个明确的"尺度参照"。
- **灯光和画面**：写出接触阴影、曝光基准、AgX 色彩管理和采样要求。
- **底线和限制**：写通用底线和本类目的底线（禁止项），再写素材规则，最后用一句"可借助 ……（内置）、……（开源）等插件"给出插件建议，至少写 2 个本类目或本模块推荐的插件，只作建议，不写成必须安装的前提。

**术语原样保留**：口语化只改句式，不改术语；去套话、改写句子时也一样，句子换掉，里面的术语要留下（例如"辉光阈值设得很高"可以改成"辉光阈值调高，只让灯丝最亮的芯泛一点光"，不能把"辉光阈值"一起删掉）。"加权法线""二次粒子""侵蚀模拟""接触阴影""尺度参照"这类词一律照原样写，不要改成大白话。

**插件规则**：只用 Blender 内置功能、官方扩展平台的免费扩展和开源免费插件；收费的商业插件一律不考虑，也不写进文件。插件只用它的建模、生成、模拟、绑定功能，不用它附带的成品模型和预设资产。

**素材规则**：可以用图像贴图（PBR 贴图）；贴图以外的外部素材都不能用：现成模型、环境贴图、扫描模型、体积数据、素材库里的成品资产。1.7 起唯一的例外：动物可以用 CC0 的动物基础网格或开源 Infinigen 生成的动物当起形的底子，但要重新雕刻出这只动物自己的比例和特征，附带的毛发梳理、贴图和姿势预设不用（见 `references/animals.md`）。文件里要用这条片子自己的话写清：东西都在 Blender 里自己建，环境光只用物理天空和场景里的光。

**风格化任务**（图形动画、卡通角色、三渲二等）：底线换成"设计质量"，即倒角一致、造型统一、配色和节奏讲究，不套用照片写实的要求。

## 5. 硬性规则（每个任务都适用）

| 项目 | 规则 |
|---|---|
| 档位 | 默认至少进阶档；只有用户明确提到基准档时才用基准档 |
| 时长 | 开头写目标时长和允许区间，例如"12 秒（时长允许 10–12 秒）"；区间在 8–15.6 秒内，上限超过 12 秒必须先征得用户同意 |
| 结尾 | 结果完整展示至少 1–1.5 秒，保留次级运动 |
| 运动 | 主体自身必须有真实可见的运动或形变 |
| 声音 | 无声音 |
| 规格 | 16:9，1280×720，30 帧/秒（以 output-spec 为准，用户另有要求时从用户），全文只写一次，并写出总帧数 |
| 软件 | 主文件第一句是"用 Blender 5.0.0 做一条……" |
| 内容 | 默认不出现人物、可读文字和真实品牌；造型原创，不照搬现有电影、游戏或真实产品（用户明确要求还原时除外，并提示版权） |
| 插件 | 只用内置和开源插件 |
| 素材 | 只允许贴图 |
| 用语 | 口语化，描述画面、运动、节奏和镜头，可以用专业术语；严禁"写脚本/写代码"、代码指令、API 函数名、属性变量名或编程步骤 |

| 写法 | 像懂行的导演当面交代：口语化、数字取整、适当缩写；专业术语照原样写；不写坐标、色值、零点几秒和推导出来的物理量；不写代码或属性名 |
| 文件 | 只输出主文件、考点说明和 rubric.json 三个文件；**不输出单独的剧本文件**，剧本内容（时间线、动作、镜头、构图、光线、色彩）都写在主文件里 |

## 6. 第二步：输出文件

每个任务一个文件夹，里面三个文件（格式见 `references/brief-template-v3.md`）：

| 文件 | 用途 | 编码 |
|---|---|---|
| `<标题>.md` | 主文件，交给制作方 | UTF-8 带 BOM（Python 用 `encoding='utf-8-sig'`） |
| `<标题>考点说明.md` | 内部校验用，不交给制作方；写主类目、档位、规范版本（进阶版 1.7）、视觉基调、考点，以及“类目与标签”（归类理由 + 11 个标签组） | UTF-8 带 BOM |
| `rubric.json` | 验收评分表 | UTF-8 不带 BOM |

- 主文件依次是开头一段和五个二级标题：场景和主体 → 动作和镜头 → 关键效果和做法 → 灯光和画面 → 底线和限制。每个事实只写一次。
- 主文件里不能出现"考题""考点""考察"字样，也不写考点编号、分级、档位、耦合链、类目和标签；这些都写在考点说明文件和回复里。
- **标签**：按类目表第三、四节选：视觉造型、渲染风格、动态节奏、灯光氛围、背景环境、时序结构、复杂度等级各单选 1 个；材质质感 1–3 个，第一个是主材质；动画行为 1–4 个，其中正好 1 个主行为，主行为只能来自位移与运动、结构与装配、形变与生长、物理与特效；色彩基调（0–1 个）和应用场景（最多 2 个）是选填，不填时写“不填”和理由。标签名必须和类目表完全一致。
- `rubric.json` 按 `references/rubric-guide.md` 写：通用项 + 数量硬指标项（3.7 表里适用的每一行各一项，都是关键项）+ 关键项“材质与制作底线” + 类目专项 + 每条关键效果对应的任务项 + 加分项 + 3.4 的三个关键项（动态密度、电影级画面、细节精致度）+ 进阶版的关键项"海报帧与视觉基调"，一般 20–26 项；只依据主文件，不加隐性要求。
- 修改时三个文件一起改：动作变了，考点说明的"作用对象与时段"和 rubric 里对应项的锚点也要跟着改；rubric 的已有编号保持不变。
- 文件名和标题都不带版本号。

## 7. 写作要求

- **口语化**：像导演当面跟制作方交代，短句、日常用词，先说要什么再说怎么做；禁止项用"别……"。**口语化只改句式，专业术语照原样写**。对照表见模板。
- 所有尺寸、距离、速度、时间都写成具体数字，并说明是参考值。
- 动作按秒写清"谁在什么时候做什么，环境怎么响应"；第一帧就要在动。
- 写实类任务再按 `references/realism-checklist.md` 补材质和结构细节；用户说"更写实""更炫酷"时，按清单、丰富度要求和制作底线加细节，但守住 3.4 的主次规则。
- 检查物理和镜头逻辑，例如镜头要停到某物的后上方，那么它必须先从镜头下方经过。

## 8. 校验（每次修改后都要跑）

```bash
python3 <skill 目录>/scripts/check_brief.py <任务文件夹>/<标题>.md
```

脚本按文件格式自动选择规则。3.0 格式会检查：

- 主文件：BOM、开头句式、目标时长和允许区间、规格和总帧数、五个二级标题、"第 X–Y 秒"段落从 0 首尾相接写到结尾且不少于 4 段、结尾句、关键效果的时段标注、代码类用语、考点类用语、外部素材、商业插件、插件建议、基本几何体底线；
- 制作底线（3.3 起）：本类目和技术模块的专业术语写进了多少（至少 5 个且不少于三成）、插件建议里是否有至少 2 个推荐插件、通用底线（PBR 贴图或程序化纹理、倒角、接触阴影、AgX、采样、100% 查看细节、尺度参照、防重复）是否齐全、是否有一条材质做法、每条关键效果是否写了方法、重模拟是否不超过 2 种、考点说明里是否有制作底线清单；
- 进阶版各项（按考点说明的"规范版本"执行：最新版本全部按 ERROR 查，旧版本的任务只对后来新增的项提醒或不查）：
  - 防穿模（1.5 起，所有进阶版任务都查，不分版本）：有接触清单那一句（至少 3 个"第 S 秒"，提到线框、X 射线或逐帧）；写了重模拟的那条有碰撞体或障碍物的做法；有走路、爬行、助跑的写了反向动力学和贴地、锁脚；rubric 有关键项"接触与防穿模"。
  - 写法：没有坐标、色值、三位以上小数和传感器参数；时间是否过细、篇幅是否超过 7,000 字（提醒）；套话和跨任务整句重复（提醒）。
  - 风格：开头只有一个风格参照，不用"又有/只是……一点/带一点……感"叠风格；视觉基调和风格参照不打架；写实渲染（按考点说明的"视觉造型"和"渲染风格"标签判断）里不正面出现水墨、山水画、三渲二；定格和运动模糊不同时要；题材本身很鲜时不用 Punchy；"黑金奢华"标签只配产品广告。
  - 基调和镜头：视觉基调在基调表里、和考点说明一致，光比、焦距和 AgX 观感在范围内；每段交代镜头和构图；特写、焦点、焦距、光圈；对角线和三分法各最多一段；至少 2 段写主体占画面多大。
  - 动态：一直在动的东西至少 8 样且有远处的；A–N 动态覆盖至少 10 类、四层齐全（提醒）。
  - 还原和优先级：关键效果的还原数值、至少 2 条退路、"先保住"那一句。
  - 光和色：3 层光、软硬、轮廓光/逆光/实用光、色温、光比、大气效果；主色/辅色/点缀色和面积比例、饱和度、色彩脚本、最亮、主体和背景差几档、暗角、颗粒、AgX 观感；海报帧 2–3 个时刻和自查；渲染那一句。
  - 粒子和质感：粒子的大小和前后分层；质感那一条至少 3 个带单位的物理特征和高光。
  - 建模和动植物：灰模自查那一句；写了瀑布却没分段写水舌、水指、落点白沫（提醒）；正文不正面写用基本几何体做东西；动物出现时写结构拆解（提醒）；每秒十几次以上的振翅要写成虚影或放慢（提醒）。
  - 材质细节（1.6 起）：写实任务里出现树时，要写根张或板根、树皮沟深（带单位）和贴图方向或三平面投影；出现建筑时，要写至少两处按高度或朝向分布的风化（返潮、泥溅、流痕、青苔、锈痕、磨亮等）；出现动物时，表皮要写到带单位的尺寸。
  - 动物（1.7 起）：写实场景里动物是主要元素时，要写体长和部位比例、附肢或羽鳍的数量、表皮尺寸、沾了什么环境、动作的真实数值、骨骼绑定；rubric 有关键项"动物形体与动作"。"鱼尾纹""鸟瞰""马赛克"这类词不再被当成动物。
  - 细节和制作底线：三级细节和至少 8 样近看的小细节；考点说明"制作底线清单"里的每个专业术语都写进了主文件；近景贴图精度。
- 考点说明：主类目是否在类目表里、标签组是否齐全、标签名和数量是否符合类目表规则、主行为是否唯一且合规、考点名称和分级、配方、档位下限、档位来源、耦合链、最高分级；
- `rubric.json`：合法 JSON、不带 BOM、评分策略、编号连续、权重为正且合计 100、关键项和通过线、评分档位、锚点完整、时长项和主文件的区间一致，以及主类目对应的数量硬指标项是否齐全、是否为关键项、是否写出了数量；3.4 起还有三个电影级关键项，进阶版还有"海报帧与视觉基调"。

脚本查不出来、回复前要自己核对的：术语是不是用在了对的地方（不是为了凑数堆在一起）；考点是否强耦合；rubric 有没有引入主文件里没写的要求；丰富度和动态形式是否真的满足最低要求；物理和镜头数字是否自洽。有 ERROR 必须修好；WARN 要逐条确认。

## 9. 旧格式（仅用于修改旧任务）

本 skill 只用于写进阶版的新任务。修改 3.4 及以前的任务（包括 2.x 和 1.x 格式），用 `animation-brief` skill 处理；用户要求把旧任务升级成进阶版时，按本 skill 的规则重写三个文件。

## 10. 提交

- 遵守仓库的分支规则：当前分支不是 main/master 时直接提交到当前分支；是默认分支时新建分支。
- `git add` 只加明确的文件路径；提交后 `git push`，再用 `gh api "repos/<owner>/<repo>/git/trees/<branch>?recursive=1" --jq '.tree[].path'` 确认文件已经在远端。
- 回复里给出 GitHub 链接：`https://github.com/<owner>/<repo>/blob/<branch>/<路径>`。

## 11. 效果图（只在用户要求时做）

- 默认按 3 个关键时刻各出 1 张，1280×720，放在 `<任务文件夹>/效果图/`。
- 做法见 `references/mockup-guide.md`；下载 Poly Haven 资源用 `scripts/fetch_polyhaven.py`。效果图只用于内部预览，用到的模型和环境贴图不能写进主文件。
- 先出低分辨率测试图，确认没有明显问题后再渲染终稿；交付时如实说明效果图和方案的差距。

## 12. 回复用户的格式

**第一步（创意建议）**：创意方向表格 → 推荐的方向和理由 → 需要用户决定的问题（带默认答案）。

**第二步（输出文件）**，依次包含：

1. 三个文件的链接，并注明考点说明不交给制作方。
2. 时间线表：时间｜段落｜画面（标出起因、关键过程和结果分别在哪一段）。
3. **类目与标签**：主类目（完整路径）和一句归类理由，再加一张标签表（标签组｜选定标签｜必要说明），和考点说明文件里的一致。
4. **硬指标对照**：表格列出 3.7 里适用的每个硬指标、要求的数量和本片的实际内容。
5. **丰富度与动态清单**：一张表列出前景、中景、远景的元素和尺度参照；一张表列出动态（A–N 类别、内容、来源、时段）。这是回复里的说明，主文件里不写这种表。
6. **电影级画面**：一张表列出每段的构图方式、光的层次和色温、配色和色彩脚本、焦距光圈和焦点安排、特写和微细节。
7. **视觉基调与镜头**：选定的视觉基调和理由；每段的镜头和构图；海报帧；渲染要点。
8. **考点与指南说明**：每个考点的编号、名称、分级、考察核心（一句话）和在本片中的体现。
9. **考察点与难度情况**：档位和配方、耦合链、难度来源和最容易穿帮的点、片中有但没列为考点的效果、升档的调整方法。
10. **rubric 摘要**：表格列出编号、维度、权重、是否关键。
11. **制作方法说明**：技术模块、关键底线和术语、推荐插件。
12. "我自己定的默认设定"（编号列出），以及仍在等用户回答的问题。

不写开场白和结尾客套话，不复述用户已经知道的内容。
